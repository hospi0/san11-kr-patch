# 14 — 시나리오 아카이브(s11pkres KOEI%SAN11) 구조 해독 (2026-07-18 세션12)

> 옛 문서(02·03·05)의 "시나리오 산문 382,511자" 추정은 **덤프였다**. 이 세션에서 실제 구조를
> 뜯어보니 진짜 신규 번역량은 훨씬 작고(추정 ~8.2만자), 나머지 대부분은 **이미 번역된 자산의 재사용**이다.

## 핵심 발견: `0000feff`/`KOEI%SAN11` 컨테이너 = 캠페인 시나리오 1개당 1파일

`s11pkres.bin` idx **6~21**(idx5 제외, 16개) — 각 175,159 B, 고정 레이아웃:

```
0x00  0000feff magic
0x04  count (u32) — 활성 세력 수 (전부 22로 관측됨)
0x08  "KOEI%SAN11" + 0패딩 (16B, ~0x18까지)
0x18  u32=1, 0x1c u32=3 (상수 추정) + 0패딩
0x58  가변 헤더(체크섬/ID 2B 등, 시나리오마다 다름)
0x5f  시나리오 제목 (가변길이, null패딩)
0x70  시나리오 개요문 — **고정 오프셋**(제목 길이 무관), 250~300자급
0x1a2 숫자 테이블(용도 미상, 도시/세력 배치 추정)
0x275 세력별 공략문 배열 — **고정 오프셋, stride 0x138(312B) 고정**
      슬롯당 최대 2개 텍스트(22세력×2=44 매치, 관측 43~44) — 미사용 슬롯은
      "難易度ともに未作成"(난이도 모두 미작성) 플레이스홀더 텍스트로 채워짐(번역 대상 아님)
0x3bcc~ 무장 이름 인덱스 — 姓/名/読み만, roster_kr.tsv와 **완전히 같은 순서(idx 0~899)**
0x6b45~ 무장 전체 레코드 — 姓/名/字/読み + 스탯(ff ff ff ff 40 00... 접두) 반복,
      역시 roster_kr.tsv와 같은 순서로 확인(idx80~83 = 夏侯和/恵/玄/尚 일치)
0x29119 용어사전(역사/왕조 용어, 표제어+읽기+설명 고정폭 컬럼) — **idx13과 idx21이 바이트 완전 일치**
      = 전 컨테이너 공용, 6,942 B(≈1,085 CJK자) — 번역 1회, 패치는 여러 곳
```

idx=5(47800B)만 다른 레이아웃 — 도시명 테이블로 시작(제목/개요 없음). "전투 시나리오(단일 맵)" 계열로 추정, 미조사.

## 재사용 가능한 부분 — 신규 번역 불필요

1. **무장 이름(0x3bcc·0x6b45 두 벌)** = `work/roster_kr.tsv` **900행과 순서 1:1 일치** 확인됨
   (idx0 阿会/喃/アカイナン, idx80~83 夏侯和/恵/玄/尚 등 다중 샘플 대조). → 추출+주입 도구만 있으면 됨.
2. **idx24~61(36개, 각 1.15MB)** — 옛 census가 "산문 6,379자"로 잡았던 그 덩어리. idx24 헤더 직후
   텍스트가 `国力向上の基本`(국력향상의 기본) — 이건 **`work/e4_tutorial.tsv`(entry4 블록25·26·28,
   2,304개)에 이미 있는 문구**(grep 확인, 4건 매치). → **entry4 튜토리얼 번역이 끝나면 그 번역을
   그대로 재사용**할 가능성이 높다(idx24 쪽 정확한 레코드 매칭은 미검증 — 다음 조사 항목).
   ⚠️glossary 바이트 완전일치 테스트는 실패(idx24에 idx21의 용어사전 원문이 그대로는 없음) →
   idx24~61은 "같은 소스, 다른 포맷/재편집"일 수 있음. 성급히 재사용 확정하지 말 것.

## 신규 번역이 필요한 부분 (진짜 볼륨)

캠페인 시나리오 16개(idx 6~21, idx5 제외) 실측:

| 항목 | 수량 | 글자수(추정) |
|---|---|---|
| 시나리오 개요문 | 16개 | ~4,500자 |
| 세력별 공략문(플레이스홀더 제외) | 665개 | 76,501자 |
| 역사 용어사전(공용, 1회 번역) | 1벌 | ~1,085자(6,942B) |
| **합계** | | **≈82,000자** |

옛 추정 382,511자보다 훨씬 작다 — 차이는 로스터(재사용)·중복 사전·플레이스홀더를 산문으로
잘못 계상했던 것. **`analysis/text_census.py`의 mass 측정은 raw SJIS 바이트 유효성만 봐서
로스터/스탯 테이블도 "산문"으로 카운트했다** — [[feedback_scan_coverage_and_detectors]] 재발 사례.

## 미확정 / 다음 조사

1. **세력별 공략문 44슬롯의 정확한 의미** — 22세력×2(추정: 통상/困難모드? 또는 세력소개+공략팁 분리?)
   구조 확정 필요. 슬롯 앞 1바이트(\x01~\x04)의 의미(난이도 별? 아이콘?)도 미확정.
2. **0x1a2 숫자 테이블** — 도시/세력 배치로 추정, 미해독. 번역과 무관할 수 있으나 확인 필요.
3. **레코드 경계 확정** — 세력별 공략문·무장레코드 모두 "고정 stride로 보인다"는 관측이지 아직
   전수 검산은 안 했다(entry5 교훈: 표본 몇 개로 stride 확정하면 안 됨 — 16개 컨테이너 전수 검산 필요).
4. **idx5(단일 시나리오/전투) 레이아웃** — 완전 별도, 미조사.
5. **idx24~61 정확한 구조** — 튜토리얼 재사용 가설 검증(레코드 단위 매칭), 36개가 서로 동일한지도 미확인.
6. **패치 경로** — s11pkres는 LINK 아카이브라 엔트리 자유 재배치 가능(entry3/4처럼 RAM 슬롯 제약이
   있는지는 미확인 — 이 아카이브 엔트리들은 실행 중 어떻게 로드되는지 자체가 미조사).
7. **화면 표시 제약(폭/줄바꿈/스크롤)** — 개요문·공략문이 화면에서 어떻게 렌더되는지(자동스크롤인지
   가로잘림인지) 실기 스크린샷으로 확인 안 됨. entry4 결전 설명칸과 같은 화면일 가능성 있음.
