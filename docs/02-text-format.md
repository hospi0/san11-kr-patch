# 02 — 텍스트 위치와 포맷

## 핵심 결론
**게임 텍스트는 평문 SJIS(cp932)로 저장** — 압축 없음. 프로젝트를 죽일 수 있었던 최대 리스크 해소.

> ⚠️ 조사 주의: raw 스캔에서 "6자 이상 연속 JP"만 필터하면 **짧은 이름 테이블을 놓친다**(초기 오판 원인). 무장명을 SJIS 바이트열로 직접 검색해야 정확. (`tools/analysis/search_names.py`)
> 검증: 아카이브에서 曹操 174회·劉備 91회·武将 517회·董卓 93회·袁紹 88회. 실행파일에도 존재.

## 텍스트 3종

### 1) UI / 커맨드 텍스트 — 실행파일 내
- 위치: `SLPM_667.01` 파일 **~0x443c00** (VA 0x543b00) 부터.
- 깨끗한 널패딩 SJIS 슬롯. 전체 커맨드 체계: 徴兵·訓練·武将登用·同盟·停戦協定·軍団編制·外交·舌戦… 그리고 printf 포맷("%d人プレイ", "《%3d年%02d月%s》" 등) 보존.
- 편집: in-place. 슬롯 경계·포인터 주의. (`tools/analysis/struct.py`가 이 영역 덤프 — 단 파일명이 표준모듈과 충돌하니 실행 시 rename)

### 2) 시나리오 산문 / 군주별 전략지침 / 역사 서사 / 튜토리얼 — 아카이브
- 위치: `0000feff`/KOEI%SAN11 컨테이너 (idx=6, 11 등 다수, 각 175159B급).
- **idx=24 = 1,149,133B 대형 텍스트 컨테이너** (2026-07-16 발견, 폰트 탐색 중 우연히). 헤더 count=0x0c, 0x60부터 SJIS 제목: 「国力向上の基本」 등 **튜토리얼/도움말 본문**. 지금까지 파악된 것 중 최대 단일 텍스트 덩어리 → 번역 볼륨 산정 시 반드시 포함.
- 구조: `[03]`/`[04]` 레코드 구분자 + 널 패딩(여유공간 有). 완전한 문장.
  - 예: "劉備入蜀 … 赤壁で大勝した後、孫権は大黒柱である周瑜を失う…"
  - 예: "仇敵・曹操打倒を目指すことになる。劉備とは同盟を結び…"
- 컨테이너 헤더: `0000feff`(marker 0xfffe0000) + u32 count + "KOEI%SAN11"(16B) + [0x1c]에 타입값. 이후 긴 제로 → 데이터. **서브블록 오프셋 테이블은 아직 정밀 미해독**(idx=1 파싱 시도했으나 서브테이블 위치 불명, `tools/analysis/cont.py`).
- 편집: 번역 쉬움. 여유 패딩 덕에 길이 확장에도 어느 정도 여지.

### 3) 이벤트 대사 스크립트 — 아카이브
- 위치: `9b046e12`형 엔트리 (idx=3 등).
- 구조: SJIS 텍스트 + 제어 오피코드 혼재.
  - `[02][0a]`,`[02][0b]` = 조건/분기 추정
  - `[02][96]1x…[02][96]0x` = 이름(무장) 래핑
  - `=635`,`=98`,`=432` = 무장 ID ASCII 참조 (兄者/兄貴 같은 관계 호칭도 리터럴로 존재)
- 편집: 가능하나 **오피코드 보존 필수** (Terra MXE 유사, 단 더 규칙적으로 보임). 종료자·바이트경계 스크리닝 필요.

### 4) 무장/도시명
- 전용 이름 테이블 + 스크립트에서 ID 참조로 추정. 위치 정밀 확정은 미완.

## 위치 변환 도구
- `tools/analysis/locate.py` — 아카이브 raw 오프셋 → 엔트리 idx + 디코드 윈도우. hits 리스트만 바꿔 재사용.
