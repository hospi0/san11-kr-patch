## ★ 반각(half-width)은 선택이 아니라 필수 — 2026-07-17 확정

`encoding.py`가 ASCII를 **전각으로 바꾸고 있었다**. 이건 최적화 문제가 아니라 **버그**다:

| | 바이트 |
|---|---|
| 원본 `%3d年%2d月%2d日` | `25 33 64` 94 4e … (**반각** %3d) |
| 옛 코덱 출력 | `81 93 82 52 82 84` … (**전각** ％３ｄ) |

`％３ｄ`는 printf가 서식으로 인식하지 못한다 → **날짜가 치환되지 않고 문자열이 그대로 화면에 뜬다**.
게다가 24B라 예산도 넘는다. 더 나쁜 건 `translate_ui.py`의 예산 계산기는 ASCII를 1B로 세서
**"예산초과 0"이라고 거짓 보고**했다는 것 — 검사와 인코더의 가정이 어긋나 있었다.

**반각이 안전하다는 근거**: 반각은 2바이트 SJIS→슬롯 테이블을 거치지 않으므로 우리의 글리프
교체와 무관하다. 실기 증거 — 로스터+지명 빌드 스크린샷의 `SELECT 終了`·`R2ソート`·`L2呼出`가
전부 반각인데 정상 렌더됐다. 게임 자신도 `三國志11 with パワーアップキット`·`空き容量不足(%dKB以上必要)`에
반각을 쓴다.

→ `encode()`가 이제 반각을 그대로 낸다: ASCII 0x21-0x7E, 공백 0x20, **반각 카타카나 U+FF61-FF9F**.
**검증**: 기호·서식 원문 **171개를 인코더에 도로 넣으면 원본 바이트와 완전 일치**(실패 0).

### ⚠️ 진짜 런 **안에도** 포인터 테이블이 있다 — 쓰면 크래시
```
0x4495d0  a0 94 54 00 | a8 94 54 00 | b0 94 54 00 | c0 94 54 00
        = VA 0x5494a0   0x5494a8     0x5494b0     0x5494c0
        → 파일 0x4495a0  0x4495a8     0x4495b0     0x4495c0
        =    本体         ＰＫ         おすすめ      ステージ
```
이 포인터 바이트가 SJIS로 디코딩되어 `乃`·`ｨ乃`·`ｰ乃`·`ﾀ乃`로 잡혔다. 여기에 한글을 쓰면
**포인터 테이블이 깨진다**. → `ptr_table_mask()`가 4바이트 정렬 u32 중 데이터 구역 VA를
가리키는 게 2개 이상 연속이면 테이블로 보고 걸러낸다(12바이트 제거됨).

### ⚠️ 반각 카타카나를 "."로 뭉개고 있었다
옛 parse()는 0xA1-0xDF를 전부 `"."`로 치환했다(0xA5 `･` 가운뎃점이 "."로 둔갑). cp932로 제대로
디코드하도록 고쳤다. 메모리의 "구멍 #3(반각 카타카나 미측정)"이 이 버그다.

## 예산

in-place라 한국어가 원래 슬롯에 들어가야 한다. **원문 길이가 아니라 뒤따르는 널 개수**가 예산이다.

    budget = 원문바이트 + 뒤널      한글바이트 + 1(종료자) <= budget

뒤널 1인 문자열이 40% → 여유 0. 그런데 **한자어는 독음이 1:1이라 바이트가 같아 자동으로 맞는다**.
`translate_ui.py`가 전수 검사하며 현재 초과 0건.

**포인터는 35%(1,568개)에 있다** → 이론상 재배치로 예산을 풀 수 있다. 다만 ELF의 널 런
(71KB, 최대 15KB@0x3fea32)이 **진짜 여유인지 런타임 버퍼(zero-init 데이터)인지 미검증**이라
지금은 쓰지 않는다. 쓰려면 그 구역을 프로그램이 건드리는지 먼저 확인할 것.

## 자동 번역이 통하는 이유

**UI 한자어는 독음이 곧 한국어 번역이다.** 決定→결정, 初期化→초기화, 追放武将選択→추방무장선택,
軍団再編→군단재편, 人材探索→인재탐색, 駆虎呑狼→구호탄랑, 二虎競食→이호경식. 바이트도 동일.

한자 구간만 바꾸고 나머지는 보존한다: `%3d年%2d月%2d日` → `%3d년%2d월%2d일`, `技巧Ｐ` → `기교Ｐ`.
기호·숫자(`×` `○` `０`~`１５` `----`)는 **그대로 두는 게 정답**이라 keep으로 센다.

### 함정 1 — 구간을 자르면 두음법칙이 깨진다
한자 구간만 떼면 그 구간이 전부 어두 취급을 받는다: `%3d年` → "%3d**연**"(✗), `190年` → "190**연**"(✗).
→ **수사(숫자·printf 서식) 바로 뒤의 한자는 단위 명사**라 어중으로 처리한다(`COUNTER_PRE`).
어중 독음은 앞에 더미 한자를 붙여 번역 후 첫 음절을 떼서 얻는다(`一年`→`일년`→`년`).
공백·글자 뒤는 새 어절이라 어두: `190년 1월 조조거병` ✓, `顔CG変更年齢`의 変更年齢은 어두 ✓.

### 함정 2 — lib 독음이 그냥 틀린 글자
`台`→태(✗대) `専`→부(✗전) `担`→단(✗담) `錬`→동(✗련). 전 데이터에서 충돌 없음을 확인한
台·専·担은 `name_overrides.HANJA_OVERRIDES`로, 문맥마다 갈리는 것은 단어 단위로 잡았다:
率(統率=통솔/成功率=성공률) · 諾(承諾=승낙/受諾=수락) · 降(降臨=강림/降伏=항복/降格=강등) ·
錬(鍛錬=단련/錬兵=연병/錬成=연성).

### 함정 3 — 복합어 경계
hanja는 문자열 전체를 한 단어로 본다. `全隣接都市`→"전**린**접도시"(✗전인접도시),
`部隊編集陸上`→"부대편집**륙**상"(✗육상), `変更年齢`→"변경**년**령"(✗연령 — 変更와 年齢은 독립된 두 단어).
→ 단어 단위 교정.

### 함정 4 — 일본어 전용 한자어
독음하면 한국어가 아니다: 取引=거래 相場=시세 笑顔=미소 綺麗=아름다움 口調=말투 続柄=관계
半分=절반 婿=사위 嫁=며느리 顔=얼굴 名前=이름 根城=본거지 関所=관문 罠=함정 待伏=매복
厩舎=마구간 書物=서적 ~済=~완료(編集済=편집됨).
`初級`/`超級`은 독음이 둘 다 "초급"이라 충돌 → 超級=최상급.
