# 03 — 폰트 렌더 체계 (역공학, 핵심 문서)

capstone 5.0.7로 `SLPM_667.01`(R5900 MIPS)을 역어셈블해 폰트 렌더 경로를 추적한 결과. 모든 VA는 `파일오프셋 = VA − 0xFFF00`.

## 요약
폰트 = **RAM의 마스터 아틀라스 + 동적 VRAM 글리프 캐시(LRU)**. 글리프는 필요할 때 host→local(RAM→VRAM) 전송으로 캐시에 올라간다. 게임은 전체 JIS가 아니라 **사용 글리프 서브셋 정확히 3,773자**만 탑재하고, SJIS→슬롯 번역 테이블로 매핑한다.

**마스터 아틀라스는 압축돼 있지 않다** — `s11pkres.bin`에 raw 4bpp로 들어 있고 직접 편집 가능하다(아래 확정 절). 2026-07-16 한글 1자 PoC 실기 통과.

## 글리프 서브셋 = 정확히 3,773자 (2026-07-16 확정, 추정 아님)
파일 0x4389E0의 u16 테이블 11,264엔트리를 전수 파싱한 결과:
- 매핑된(≠0xffff) 엔트리 **3,773개**, 슬롯값 **0..3772**, **중복 0 = 완전 전단사**.
- 슬롯은 SJIS 코드 오름차순으로 배정된다(slot0=0x8140, slot1=0x8141, slot2=0x8142, slot3=0x8144 … 0x8143은 서브셋에서 제외).
- → **글리프 예산 = 3,773슬롯**. 한글 KS X 1001 2,350자 + ASCII + 기호를 넣고도 여유. 폰트 전략상 매우 유리.

## 동작 상세

### SJIS→슬롯 (함수 0x16aad0)
SJIS 코드를 구간별로 압축해 하나의 0-based 인덱스로:
- 0x8100–0x9fff: `code − 0x8100`
- 0xe000–0xeaff: `code − 0xC100`
- 0xed00–0xeeff: `code − 0xC300`
- 그 외(0xef00+): `code − 0xC400`

그 인덱스로 **VA 0x5388E0의 u16 테이블**을 조회 → 글리프 슬롯 번호 반환(0xffff=없음).
→ **한글화: 이 테이블에서 우리가 택한 코드포인트 엔트리를 한글 글리프 슬롯으로 다시 쓰면 된다.**

### 글리프 캐시 (함수 0x16ab90)
- 캐시 미스 시 마스터 글리프 픽셀을 VRAM 캐시 슬롯으로 host→local 전송. 슬롯 부족 시 사용횟수 최소(LRU) 축출.
- ⚠️**아래 옛 구조 추정은 RAM 실측으로 반증됐다 — 믿지 말 것**:
  > ~~"폰트객체 0x538000: +0x0~ 글리프→VRAM캐시위치 디스크립터 배열, +0x3cb0 144슬롯 LRU 배열, +0x3ef0 캐시카운트(0x90=144)"~~
  - 실측 시 +0x3ef0 = `0xffffffff`(0x90 아님). 애초에 0x538000+0x8E0가 SJIS→슬롯 테이블이라 0x3cb0짜리 배열이 들어갈 자리가 없다.
  - **실제로는 디스크립터가 각 글리프 뒤 24B 패딩에 인라인**돼 있다(아래 확정 절). "144슬롯"의 근거도 사라졌다 — VRAM 캐시 실측은 256×512(25컬럼×25행).

### 렌더 루틴 (0x16b7d0)
- 인자: a0=폰트객체(→s5), a2=텍스트 문자열(→s0).
- 특수코드: 0xf0b8~bb = 색상/제어, 0xf0b0~f0f1 = 가이지, **0x8140 = 전각공백(특수처리 → slot0 셀은 공백 보장 없음)**.
- (col,row) 2바이트 → ×20px UV 계산. **÷0x19(25)는 VRAM 캐시의 컬럼 수**이며 컬럼 단위는 10px다(아래 확정 절).

## ✅ 마스터 글리프 아틀라스 — 확정 (2026-07-16, PCSX2 동적분석)

**폰트는 압축돼 있지 않다. `s11pkres.bin`에 raw로 들어 있고 직접 편집 가능하다.**

| 항목 | 값 |
|---|---|
| **아카이브 위치** | `s11pkres.bin` **파일 오프셋 0x49810** (엔트리 **idx=2**, 섹터 0x93, 엔트리 크기 870,016B, 아틀라스는 엔트리 +0x10 지점) |
| **EE RAM 주소** | **0x00B10E90** (부팅 시 그대로 로드) |
| **포맷** | **4bpp = PSMT4, 20×20 px**, 행당 10바이트, 팔레트 16색(투명1 + 알파램프3 + 그레이12) |
| **피치** | **224 B/글리프** = 픽셀 200B + **패딩 24B**(32B 정렬) |
| **순서** | 슬롯 = SJIS 오름차순. 테이블 0x4389E0의 슬롯번호와 **1:1 일치** |
| **개수/크기** | 3,773자 × 224 = **845,152 B** |
| **검증** | 픽셀 754,600 B가 아카이브 ↔ RAM **바이트 단위 완전 일치** |

### 글리프당 24B 패딩 = 런타임 스크래치 (= 문서가 찾던 "디스크립터")
아카이브에선 패딩이 **전부 0**이고, 실행 중에만 오프셋 **+208, +209, +215**가 채워진다(예: `0d 80 … 08`). 즉 "글리프→VRAM 캐시위치 디스크립터"는 별도 배열이 아니라 **각 글리프 뒤에 인라인**돼 있다. (이전 문서가 0x538000에서 3,884칸 배열을 찾으려 한 것은 오독 — 그 주소엔 그런 배열이 없다.)

→ **패치 시 패딩 24B는 0으로 두면 된다.**

### VRAM 글리프 캐시 (PCSX2 텍스처 덤프로 실측)
- 캐시 텍스처 = **256×512, 4bpp**, 유효폭 250px.
- **컬럼 단위 = 10px, 셀 높이 = 20px.** 전각 글리프는 2컬럼을 차지 → 한 줄에 전각 12자 / 반각 25자.
  → 문서에 있던 "아틀라스 25열(÷0x19)"의 정체가 이것. 마스터 아틀라스가 아니라 **VRAM 캐시**의 컬럼 수다.
- 글리프는 **쓰인 순서대로** 캐시에 쌓인다(LRU) — 덤프를 보면 방금 렌더된 문장이 그대로 읽힌다.

### 재현 방법 (동적분석 절차)
1. `tools/iso.py verify <iso>` — 원본 확인.
2. PCSX2(`C:\claude\utils\pcsx2`, BIOS=`scph10000.bin` JP)로 부팅. `-fastboot -statefile <p2s> -- <iso>`.
3. 텍스트가 많은 화면(시나리오 선택 권장)에서 **F1** = 세이브스테이트.
4. `tools/p2s.py <state.p2s> <outdir>` — `eeMemory.bin`(32MB)·`GS.bin`·`Screenshot.png` 추출. ⚠️p2s는 zstd(method 93) zip이라 `zipfile`만으론 못 연다.
5. 텍스처 덤프를 원하면 ini `[EmuCore/GS] DumpReplaceableTextures = true` → `textures/SLPM-66701/dumps/`.
6. `tools/analysis/find_master.py <cache.png> <eeMemory.bin>` — 캐시 글리프 픽셀로 RAM 위치 특정.

## 🚩 전수 스윕이 폰트를 놓친 이유 (교훈)
아래 스윕은 "raw 아틀라스 없음 → 압축됐을 것"이라는 **틀린 결론**을 냈다. 실제로는 raw였다.

**원인: 지오메트리 격자에 실제 피치(224)가 없었다.** 4bpp 20×20을 `per=200`(=20×20×4/8)으로만 테스트했는데, 실물은 **패딩 24B가 붙은 224**였다. 픽셀 계산식으로 나온 "당연한" 값만 넣고 정렬 패딩을 고려하지 않은 것.

교훈: 격자 탐색에서 **음성 결과의 신뢰도는 격자의 커버리지를 넘지 못한다.** 셀 크기를 넣을 때는 계산상의 픽셀 크기뿐 아니라 **16/32/64B 정렬로 올림한 값**도 반드시 함께 넣어야 한다. 그리고 결정적 단서는 통계가 아니라 **실물 픽셀 대조**(`find_master.py`)에서 나왔다 — 에뮬레이터에서 진짜 글리프를 얻어 그 비트패턴으로 찾자 32MB에서 **유일한 1건**이 즉시 나왔다.

## 전수 스윕 결과 (2026-07-16, `scratchpad/atlas_hunt3.py`) — ⚠️이 결론은 위와 같이 틀렸음
당시 결론: "마스터 아틀라스는 어떤 raw 지오메트리로도 저장돼 있지 않다." 생존 후보 0건.

커버리지(이번엔 실제 전수):
- 대상: 아카이브 top-level 9,383 + **중첩 LINK 서브엔트리 11,257 = 20,640개** 중 크기 ≥188,650B인 1,138개 전부, **＋ SLPM_667.01 전역 슬라이딩 윈도우(0x400 스텝) ＋ Overlay1/2.bin**.
- 지오메트리 15종: 1/2/4/8bpp × 셀 20x20(packed·rowalign·pad4)·24x20·24x24·32x20·32x32.
- 헤더 오프셋 14종(0~0x1000).
- 판정: 빈 셀 <5% ∧ 셀 상/하단 여백 ≥70% ∧ 잉크밀도 정상대역 ∧ **셀 고유율 ≥80%**(주기적 노이즈 거부).

### ⚠️ 이 스윕의 남은 블라인드스팟 (정직하게 기록)
- **GS 스위즐(swizzled) 텍스처 포맷**: PSMT4/PSMT8을 미리 스위즐해 저장했다면 선형 행 렌더로 안 잡힌다.
- 셀 높이가 20/24/32가 아닌 경우, 글리프별 가변길이 저장, 슬롯 순서가 SJIS 순이 아닌 저장 순서인 경우.

## 배제 완료 (다시 하지 말 것)
> ⚠️ 이 절에 "raw 아틀라스 없음"이 한때 적혀 있었다. **삭제했다 — 그건 틀렸고 폰트는 raw다**(위 확정 절). 배제 항목을 적을 땐 반드시 커버리지와 근거를 함께 남긴다.

- TIM2 등 표준 PS2 텍스처 매직: 없음
- GCOL/K3ST/idx88·89: 각각 배경CG/압축/월드맵으로 확정, 폰트 아님
- **idx=1**(129,440B): 값이 0x00/0x01/0xff 삼진 파라미터 테이블. 폰트 아님 — 후보에서 제외.
- **idx=24**(1,149,133B): `0000feff` KOEI%SAN11 **텍스트 컨테이너**(「国力向上の基本」 등 튜토리얼/도움말). 폰트 아님 → docs/02 텍스트 소스로 이관.

## 🚩 방법론 경고 — 과거 기록의 오류
2026-07-16 이전 문서는 "전 아카이브 전수 타일렌더 → 폰트 없음, **배제 완료**"라고 적었으나 **근거가 없었다**. 당시 `sweep.py`/`sweep8.py`/`tiles.py`는 실제로:
- `for k in range(24)` — 9,383개 중 **24개만 샘플링**
- `bysize.setdefault(b,i)` — 같은 크기 엔트리는 **1개만** 검사
- 크기 50KB–3.2MB 밖은 제외, `KNOWN` 매직 필터로 **중첩 LINK 1,044개 통째로 스킵**
- W=256 고정 렌더 — **20px 글리프 셀을 한 번도 시도 안 함**

결론(“raw 아님”)은 우연히 옳았지만 근거는 부실했다. **샘플 스캔을 전수라고 기록하지 말 것.**
또한 검출기 설계 시 주의: v1은 "셀 상/하단 여백" 만 봐서 **거의 전부 0인 엔트리가 만점**을 받았고, v2는 "slot0=공백"을 값싼 프리체크로 썼는데 렌더러가 0x8140을 특수처리하므로 **진짜 아틀라스를 걸러낼 수 있는 잘못된 가정**이었다. 잉크·고유율 제약이 함께 있어야 한다.
