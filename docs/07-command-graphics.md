# 07 — 커맨드 UI = 구운 그래픽 (idx=94)

✅✅ **세션5: 83단어 전량 한글화 실기 완료** (사용자 확인 "딱좋아")

왼쪽 세로 커맨드 메뉴(都市/軍事/人材…)와 모든 액션 커맨드는 일반 폰트가 아니라
`s11pkres.bin` **idx=94에 구운 스프라이트 시트**다.

**확정 근거(세션2 실기)**: 일반 폰트 아틀라스의 都·市 글리프를 도·시로 바꾸니 하단
"都市JUMP"(일반폰트)는 "도시JUMP"로 바뀌었으나 **왼쪽 커맨드 都市는 금색 그대로** = 다른 렌더 경로.

## ★★ 포맷 (세션5 정정 — 옛 "8bpp 그레이스케일"은 틀렸다)

**4bpp · 피치 256 B = 512 px · 저니블 = 왼쪽 픽셀 · 인덱스 0 = 투명 · 1~15 AA 램프**
= **메인 폰트 아틀라스와 완전히 같은 포맷**.

8bpp로 읽으면 바이트당 픽셀 2개가 1개로 뭉개져 한자가 가로로 눌려 보인다 — 그래서 옛 기록의
"글자폭 ~22px"와 렌더가 안 맞았다. **단서는 `0x55`가 반복되는 값 분포**(= 값 5인 픽셀 2개).

- entry94: 섹터 38973 (파일 `0x4c1e800`), 540,096 B
- 헤더 `[count=17][unk=5][u32 offset×17]`(0x231b~0x71cb) = 앞쪽 아이콘용. **커맨드 그리드는 이
  테이블 범위 밖**이다.
- ⚠️**선형 4bpp로 읽히는 건 커맨드 그리드 구역뿐**. 나머지(행 0~565, 1000~2109)는 노이즈로 보인다
  = 다른 포맷(스위즐?) 또는 다른 서브이미지.

## ★ 격자 (실측 확정)

**지우는 상자(BOX)와 글자 자리(GLYPH)와 표시창(게임이 보여주는 범위)은 전부 다르다.**

```
BOX   : x = 64 + 50c (폭 50)      y = 563 + 28r (높이 28)     c,r = 0..8
        좌측 세로메뉴 열 : x = 0 (폭 50)
GLYPH : BOX 안쪽 (+2, 0) 에 46 x 26  = 23x23 글자 2개
표시창: BOX의 y 4~23 (20줄)  ← 여기 안에 잉크를 가둬야 한다
```

BOX 폭/높이 = 격자 피치와 같아서 **빈틈없이 타일링**된다(겹침 0, 잔재 0).

**전부 2글자 → 한국어 2음절 1:1이라 예산 문제가 없다**(都市=도시·計略=계략·突擊=돌격).
표는 `tools/cmd_words.py`. 자동 독음이 틀리는 일본어 고유 표현만 `OVERRIDES`:

| 원문 | 자동(버림) | 채택 | 근거 |
|---|---|---|---|
| 呼寄 | 호기 | **호출** | 呼び寄せる=불러들이다. SLPM의 「L2呼出→호출」과 용어 일치 |
| 熊手 | 웅수 | **갈퀴** | 熊手 = 갈퀴 (수전 전법) |
| 横払 | 횡불 | **횡소** | 横払い = 옆으로 후려치기 (극 전법) |
| 同討 | 동토 | **협공** | 共同討伐 = 동맹에게 함께 치자고 요청 |

※ 軍事(메뉴)와 軍師(참모)가 둘 다 「군사」로 겹치나 화면 위치가 달라 그대로 둔다(사용자 결정).

## ★★★ 자면 맞추기 — 실기 3회가 걸린 진짜 난관

### 1) 셀 경계는 임계값 없이 재라
잉크를 `>128`로 재서 y 565~587 / x 66~111로 잡았더니 **행 588에 옅은 AA가 59px 남아** 있었다.
그대로 패치하니 한글 위에 원본 한자 획이 **가로줄 노이즈**로 떴다(실기에서 사용자가 발견).
→ 경계는 **완전히 빈 행/열**로 잡는다. 빈 행 590·618·646·674·702·730·758·786 / 빈 열
113~114·162~164·212~214·262~264·312~314·362~364·412~414·462~464.

### 2) 표시창은 BOX보다 좁다 — 실기 피드백으로 역산했다
| 잉크 범위 | 사용자 반응 |
|---|---|
| y 5~24 | "위아래 조금 잘림" → 24가 잘림 |
| y 3~25 | "잘리고 너무 큼" → 3과 24~25가 잘림 |

→ **표시창 = y 4~23 (20줄)**. 두 반응이 모두 설명된다.

⚠️**함정**: 「원본 한자가 y 0~25를 채우니 나도 그러면 된다」가 오답이었다. 원본의 **0~3·24~25는
획 끝이라 잉크가 희박**해서(행당 평균 6.7px / 6.8px) 잘려도 티가 안 난다. 한글은 획이 굵어 바로
드러난다. **원본의 잉크 '범위'를 따라가면 안 되고, 보이는 창에 맞춰야 한다.**

### 3) 크기·베이스라인은 전체 음절로 잡아라
✅ **확정: EM = 19, YBASE = 21, weight = 0.5** → 101음절 전부 y 4~23에 꽉 참.

- ⚠️**`autofit` 금지** — 참조 음절 4개(동시군국)로 em을 역산하는데, **나머지 97음절이 창을 넘어
  잘렸다**. 전체 음절의 실제 잉크 범위로 직접 맞출 것.
- ⚠️**잉크 '면적' 프로파일 맞추기도 오답** — 최적화가 "더 크게"라고 답한다. 한글은 획이 적어서
  면적을 맞추려면 글자가 커진다. 맞춰야 하는 건 **범위(bbox)**다.

  없어 **미발견**. 덤프에서 「気力·耐久·治安」 라벨 시트는 별도로 존재함을 확인.

### ★도구: PCSX2 텍스처 덤프
`inis/PCSX2.ini`에 `DumpReplaceableTextures=true`가 이미 켜져 있고
`utils/pcsx2/textures/SLPM-66701/dumps/`에 **17,435장**이 쌓여 있다.
파일명 = `[텍스처해시]-[팔레트해시]-…` → **같은 텍스처+다른 팔레트**가 여러 벌로 찍힌다.
대부분(17,168장)은 256x512 = 폰트 글리프 캐시. **커맨드 시트 = 512x256**.
