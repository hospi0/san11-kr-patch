## 구조 (세션5 재규명)

```
0x00  u16 LE  = 메시지 개수 (1179)
0x02  u32 LE × 1179 = 오프셋 테이블(오름차순)
      offs[0] = 0x126e = 2 + 4*1179  ← 테이블 끝 = 메시지 0 시작
message[i] = d[offs[i] : offs[i+1]]   (마지막은 EOF까지)
```

★**자기검증**: `offs[0] == 2 + 4*count`가 정확히 맞아떨어진다.

⚠️**옛 기록의 「헤더 `9b046e12` 매직 + `0000` + u32 테이블@0x06」은 오독이다.**
`9b 04` = u16 1179(개수), `6e 12 00 00` = 매직의 뒷부분이 아니라 **offs[0] = 0x126e**.
옛 파서는 테이블을 0x06에서 읽어 **메시지 0(0x126e~0x1453, 485B)을 통째로 누락**하고 인덱스를
1씩 당겨 놨다. 경계가 같아 텍스트 내용은 무사했지만 **그대로 리빌드했으면 메시지 0이 사라진다.**

| 구간 | index | 내용 | 처리 |
|---|---|---|---|
| 파트1 | 0~415 | 호칭·어미 조립 테이블 | ⛔ 번역 금지·바이트 보존 |
| 파트2 | 416~1178 | 평문 763개(스킬설명·세이브·도움말·튜토리얼) | ✅ 번역(762 + 공백 1) |

**파트1** = 동적 대사 조립: 인칭(わらわ/朕/余), 호칭(兄者/陛下), `ESC M(1b4d)=성격 0~15`,
`ESC K(1b4b)=인물 ID`, `<04><02>` 제어. 건드리면 대사 조립이 깨진다.

## 인코딩

- 한자 = 전각 SJIS 2B / 가나 = **반각 카타카나 1B**, 기본은 **히라가나로 렌더**(ｽﾙ→する)
- **`ESC K(1b4b)` 또는 `ESC k(1b6b)` … `ESC H(1b48)` 구간만 카타카나 렌더** = 외래어
- `0a`={N} 줄바꿈 / `05`=구분 / `f0xx`={BTNxx} PS 버튼 가이지(15종, 전부 f0 리드)
- **`02` = 변수 삽입코드 — 길이가 파라미터에 따라 다르다**:

| 파라미터 | 길이 | 뜻(문맥 추정) |
|---|---|---|
| `0a` `0c` | 3B (`02 XX YY`) | 武将名 |
| `14` `28` | 3B | 勢力名 |
| `1e` | 3B | 군단·세력 |
| `3c` | 3B | 都市名·施設名 |
| `82` | 2B (`02 XX`) | 수치 |
| `83` | 2B | 수치(변경 후) |
| `8c` | 2B | 명칭(兵種·特技·能力) |

### ★세션5 버그 3종 (사용자가 mojibake 6줄을 지적해 발견, 36줄 영향)

1. **`02`를 1B로 읽었다** → 파라미터가 다음 한자의 리드바이트와 합쳐져 없는 글자가 됐다:
   `02 8c | 8c6f 8cb1`(経験) → `{C02}` + `血`(8c8c) + `o`(6f) + `験` = **「血o験」**
   **근거 3중 (31곳 전수, 예외 0)**:
   - part2에 남는 제어바이트가 `0a`(줄바꿈) 하나뿐으로 깔끔히 떨어진다
     (옛 파싱은 0a 44개, 그중 6개가 실은 `02`의 파라미터였다)
   - param≥0x80은 항상 텍스트가 뒤따르고(番に·`)`·を·経験), <0x80은 항상 ASCII 1자가 뒤따른다
   - ★**YY를 코드로 흡수해야 모든 메시지가 문법적 일본어가 된다**:
     `02 3c 33`+の金が0に → `3の金が0に`(비문) vs `[都市名]の金が0に`(정상)
2. **ESC k(1b6b)를 히라가나로 처리** → `ソート`(정렬)를 `そーと`라는 뜻없는 글자로 냈다(12곳).
   ESC k도 카타카나 모드다.
3. **헤더 오독으로 메시지 0 누락**(위 구조 절).

### 정규화 (인코더가 지켜야 할 것)

원본 데이터를 재보고 확정했다:
- **반각 구두점(`｡｢｣､･`)은 part2에 0회** → 「」、。・는 **항상 전각 2B**
- **장음 `ー`는 전각(81 5b) 56회가 정본**. 반각 `ｰ`(b0)는 12회뿐인데 **전부 ESC k 구간**
  = 버튼바 「ソート」 전용 변종
- **ESC는 카타카나 런에 딱 붙여 닫는다** — 전각 `ー`조차 구간 밖으로 밀어낸다:
  `ESC K デ ESC H ー ESC K タ ESC H を`

## ★섹터 예산 = 중복 엔트리 공유 (`tools/help_reloc.py`)

반각 가나 1B → 한글 2B라 entry3가 **121,593 → 127,884 B (+3섹터)**. 그런데 아카이브는
**빈틈이 정확히 0**이다:

```
헤더+테이블 75,776 B (37섹터) + 엔트리 517,677,056 B = 517,752,832 B = 파일크기 정확히 일치
엔트리 간 gap: 0곳
```

제자리에서 키우면 뒤가 전부 밀려 즉시 오버플로.

**해법: LINK 엔트리는 (섹터오프셋, 바이트크기) 쌍일 뿐이라 두 엔트리가 같은 섹터를 가리켜도 된다.**
아카이브엔 내용이 **바이트 동일한 중복 엔트리가 4,145개 ≈ 110 MB** 있다(같은 5,088B 블롭이 2,336벌!).

1. 중복 엔트리 V를 쌍둥이 T의 섹터로 재지정 → V는 여전히 같은 바이트를 읽는다(게임엔 무변화)
2. 비워진 V의 섹터에 새 entry3를 쓰고, entry3의 LINK 엔트리를 그리로 재지정

★**근거: 원본 아카이브에도 이미 같은 (오프셋,크기)를 공유하는 엔트리 그룹이 1개 있다** = 포맷이
공유를 실제로 쓴다는 증거. 읽기 전용 아카이브라 안전하고, 내용 동일은 SHA-1로 확인한다.

실제 적용: **idx 2511**(= idx 2504와 내용 동일, 81섹터 할당)을 비워 **섹터 220901**에 entry3(63섹터) 이사.
→ **diff = LINK 테이블 16 B + 새 데이터 63섹터뿐. 파일 크기 불변 → ISO in-place 유지.**
→ **남은 여유 ≈110 MB** = 앞으로 산문 382,511자를 넣고도 남는다.
