## ⚠️ 이번 세션에 뒤집힌 옛 주장 4건

### 1. "총크기 유지하면 자유 확장 — 여유 큼" → **틀림**
아카이브는 **꼬리 여유 0**으로 꽉 차 있다(엔트리 간 gap 0건, tight end = 517,752,832 = 파일크기 정확히 일치).
**진짜 예산 = 엔트리별 섹터 패딩 9.2 MB뿐이고 파편화**돼 있다(중앙값 1,056 B, 39개 엔트리는 64 B 미만).
자기 섹터 경계까지는 **공짜 성장**(오프셋 불변, 뒤 엔트리 안 밀림). 넘으면 뒤가 전부 밀려 **즉시 오버플로** →
다른 엔트리에서 섹터를 회수해야 한다. `tools/link.py rebuild`가 총크기 초과 시 거부한다.

### 2. "idx=24 = 1.15 MB 역대 최대 텍스트덩어리" → **틀림 (크기≠볼륨)**
idx=24는 1.15 MB지만 **산문은 6,379자뿐**이고, 튜토리얼 본문이 아니라 **용어·인명 사전**이다.
같은 사전 블록이 **idx=24~53 시나리오 파일에 반복**된다(24개 서로 다른 블롭인데 산문통계 mass/kana/variety가 완전 일치)
→ 한 번 번역해도 **여러 곳에 패치해야 한다.**

### 3. "idx=3 = 이벤트 대사 스크립트" → **틀림**
실제로는 **호칭·어미 조립 테이블**이다. の 0회, 曹操 0회, 兄者 26회.
```
0x2000  伯母様 / 伯母上 / 伯父様 / 伯父上        ← 호칭
0x8000  ﾀﾞｿﾞ / ﾃﾞｽﾖ / ﾃﾞｽ                      ← 반각 카타카나 어미
```
캐릭터 성격별 말투를 조립하는 용도. **아직 진짜 이벤트 대사는 못 찾았다.**

### 4. **중첩 LINK엔 산문이 없다**
1,044개 중첩 LINK(서브엔트리 11,257개)를 재귀로 전부 훑었으나 **산문 0**.
옛 census가 잡았던 "중첩 LINK 126,103자"는 **전부 픽셀 노이즈**였다(아래 4라운드 참조).
※ 중첩 LINK 헤더는 **자기 섹터크기(0x10)**를 쓴다 — 최상위 0x800을 가정하면 안 된다.

## 검출기 — 네 번 틀리고 다섯 번째에 맞았다

볼륨 추정치 변천: **19,925,187 → 550,230 → 382,511자**. 매번 "그럴듯한 숫자"가 먼저 나왔다.

### R1. 글자수 = 노이즈 (19.9M자)
랜덤 바이트의 **~13%가 유효 SJIS 페어를 시작**하고 cp932가 디코드해준다 →
**폰트 아틀라스(idx=2, 순수 4bpp 픽셀)가 40,409"자"로 채점**. 1차 결과 "7,315엔트리/19.9M자"는 전부 노이즈.
→ 대조군 교정: run≥8 연속 SJIS는 우연히는 안 나온다(0.13⁸). idx=2·70 모두 **mass≥8 = 정확히 0**.

### R2. mass8도 거짓양성 — 8bpp 이미지
음성대조군을 4bpp·바이너리로만 잡은 게 커버리지 구멍. **8bpp는 통계가 다르다**(매끄러운 픽셀이 긴 run을 만듦).
**디코드해서 읽는 것**만이 판별법이었다:
```
idx=676 GCOL  mass 20,116  '屁栢嚶劒禦嚥利漉剔吏貯囎剱'   ← 배경 CG
idx=1015      mass  8,196  '末摩末摩末摩…'                ← 픽셀
idx=91        mass  6,167  '珥珥珥珥…'                    ← 픽셀
진짜 idx=21  '劉表、劉虞と友好関係にあり、董卓、袁術と激しく対立している。領地は陳留。'
```
⚠️ **내가 양성대조군으로 찍었던 idx=1015·91·93이 실은 노이즈였다** — mass가 높다는 이유로 텍스트라 가정한 것.
**점수로 대조군을 고르면 검출기가 자기 노이즈로 자기를 교정한다.**

### R3. run≥8은 과소계상 (짧은 레코드 누락)
idx=24의 제목 「国力向上の基本」부터가 **7자**다. run≥3으로 재면 idx=24가 1,290 → 6,379자(**4.8배**).
→ **분류는 run≥8(견고), 측정은 run≥3(정확)** 2패스.

### R4. ★카타카나는 신호가 될 수 없다 (550,230 → 382,511)
**재귀했더니 총량이 100,006자 줄었다** — 재귀가 텍스트를 잃는 건 불가능하므로 평면 조사가 틀린 것이다.
범인: idx=2050의 "텍스트"가 **「ャャャャャャャ…」** — ャ 하나의 반복. **kana_frac이 1.0**이다(ャ도 가나니까).
→ **히라가나 + 조사**만이 위조 불가능한 신호다. 이미지 바이트는 히라가나 블록에 안 떨어지고, 반복 필러는 코드포인트가 1개다.

| | 히라가나 | 조사(の·に·は·を…) |
|---|---|---|
| 노이즈 (2050 ャャャ, 676 GCOL, 1015, 2518) | **0.000** | **0.000** |
| 진짜 산문 (21, 13, 5, 24) | 0.244~0.427 | 0.174~0.292 |

**정확히 0.000 대 0.24+** → 임계 0.05.
⚠️ **variety(고유율)로는 못 잡는다** — GCOL 노이즈 0.060으로, 진짜 산문 idx=5(0.088)와 겹친다.

### 최종 검출기
```
분류: run>=8 + hiragana/particle >= 0.05 + zero_frac<=0.90 + variety>=0.02
측정: run>=3
```
대조군 회귀테스트: idx=2 아틀라스 mass 0 / GCOL·2050 hira 0.000 / 산문 hira 0.24+.

## 발견된 구조

### 시나리오 컨테이너 (175,159 B, idx 5~21) — 산문 본체
- `rel 0x00b0` — 시나리오 산문: 「魏は曹操、曹丕、曹叡、夏侯惇、荀彧、司馬懿ら。呉は孫堅、孫策…」
- `rel 0x29119` — **용어·인명 사전 테이블** (idx=24와 같은 계열). 레코드 ~88 B:
  ```
  [id:u8][0xff][flag] 00 00 00  [표제어 SJIS] 00…  [읽기 카타카나] 00…  [설명 SJIS] 00…
  예: 0e ff 01 … 黄巾 … コウキン … 張角が結成。頭に黄色の巾を巻いたことに由来する
  ```
- 최대 엔트리: idx=21(11,875자), idx=13(11,841자), idx=5(11,707자).

## ❗ 무장 명부(800명)를 못 찾았다 — 미해결

**평문 SJIS로 된 무장 로스터가 아카이브 어디에도 없다.** 근거(커버리지 명시):
- 9,383엔트리 전수, 무장 20명 프로브 → **8개 이상 포함 엔트리는 14개뿐이고 전부 시나리오 컨테이너**(idx 7~21, 20개 중 8~19개).
  이건 로스터가 아니라 **산문 속 언급**이다(실제 디코드로 확인).
- 카타카나 읽기(ソウソウ·リュウビ·カンウ·チョウヒ·ショカツリョウ·リョフ) → **컨테이너당 정확히 1회씩, 총 52회**. = 인명사전이지 로스터가 아니다.
- `SLPM_667.01` 5.2 MB 전수 → 무장 17히트·도시 1히트, **밀집 클러스터 0** = 실행파일에도 없다.

**남은 가설 (미검증)**:
1. **姓/名 별도 필드** — 삼국지 시리즈는 성과 이름을 따로 저장한다. 그러면 "曹操" 연속 바이트가 로스터에 존재하지 않는다. ← **가장 유력**
2. **가이지 혼합 커스텀 인코딩** — 아래 참조.
3. **`Overlay1.bin`/`Overlay2.bin`/`modules/`/`pkres/` 미확인** ← **다음 세션 1순위, 아직 한 번도 안 봤다**
4. 압축.

## ★ 가이지(外字) 발견 — 인코딩 계획에 영향

**cp932로 인코딩 불가한 무장·도시명이 실재한다**: `龐統` `許褚` `賈詡` `公孫瓚` `鄴` `下邳`.
게임은 이들을 **가이지(char ≥ 0xF0B0, 가이지 포인터테이블 VA 0x538750 / 파일 0x438850)**로 그린다.
→ 옛 기록의 가이지 테이블이 왜 존재하는지가 이걸로 설명된다.
→ ⚠️ **한글 인코딩 계획에 영향**: 이 가이지 슬롯들은 **고유명사에 실제로 필요한 한자**를 담고 있으므로 한글 운반체로 회수하면 안 된다.
