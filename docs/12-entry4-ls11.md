# ★★★ LS11 컨테이너 포맷 — 해독 완료

```
0x000  "LS11" + 0패딩 12B
0x010  256B = 0~255의 **순열** (고유 256/256 확인) = 허프만 심볼 테이블
0x110  블록 테이블: (압축크기, 원본크기, 데이터오프셋) × 30, 전부 **u32 빅엔디안**
0x278  (테이블 끝)
0x27c  블록 데이터 시작 = 블록0의 오프셋(636)과 일치 ★자기검증
```

⚠️**엔디안이 빅엔디안**이다. PS2는 LE지만 이 테이블은 BE로 읽어야 말이 된다.

## 검산 (전부 통과)

- **오프셋 체인**: `off[k+1] == off[k] + comp[k]` 가 **30블록 전부 성립** ✅
- **크기**: 압축 합계 708,632 + 헤더 636 = **709,268 = entry4 크기 정확히 일치** ✅
- **원본 합계 1,216,275 B** (압축 708,632 → 1.72x)
- **블록0 원본크기 75,218 = 환경설정 풀 크기와 정확히 일치** ★

| 블록 | 압축 | 원본 | 오프셋 | |
|---|---|---|---|---|
| 0 | 42,721 | **75,218** | 636 (0x27c) | ★환경설정 텍스트 풀(749 메시지) |
| 1 | 34,627 | 73,860 | 43,357 | |
| 2 | 25,367 | 57,457 | 77,984 | |
| … | | | | 총 30블록 |
| 29 | 43,550 | 61,097 | 665,718 | 끝 = 709,268 = entry4 크기 |

「709KB가 75KB로 팽창」이라던 모순은 이걸로 풀렸다 — **30블록이고 블록0이 그중 하나**다.

## 압축 알고리즘 = 허프만 (심볼 테이블 확정, 비트코드 미해독)

**0x10의 256B 순열 = 빈도순 정렬된 심볼 테이블**이고 30블록이 공유한다. 근거:
- 풀(정답 출력)에서 **최빈 바이트 `0x05`(6,541회) = 순열의 0번째** ✅
- 상위 20개 바이트의 **순열 위치 평균 18.8 / 256** = 압도적 앞쪽 편중
  (완벽한 빈도순은 아닌데, 순열은 **30블록 전체 기준**이고 나는 블록0만 쟀기 때문)
- 비트스트림: 1비율 **0.641**, `0xff`가 평균의 **16배** = 비트 단위 엔트로피 코딩

**남은 것 = 비트→심볼 코드 할당 규칙.** 블록 안에 코드길이 테이블이 안 보인다
(블록0 선두 = `fc 2a 3f 6d fb ec 71 fa…` 로 바로 비트스트림처럼 보인다).
→ 가설: ①코드길이가 블록 비트스트림 앞머리에 인코딩 ②순위(rank)에서 코드가 암묵적으로 결정
  (고정 트리 모양) ③SLPM의 디코더 루틴을 읽어 확정.
